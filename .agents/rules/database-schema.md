# WeFit — Database Schema

## Overview

WeFit uses **polyglot persistence** — different database technologies for different services based on their data access patterns:

| Service         | Database   | DB Name               | Rationale                              |
|-----------------|------------|----------------------|----------------------------------------|
| UserService     | PostgreSQL | `wefit`              | Structured user data, relational integrity |
| ActivityService | MongoDB    | `WefitActivitydb`    | Flexible metrics schema, document-oriented |
| AiService       | MongoDB    | `AiRecommendationsdb`| Flexible recommendation structure       |

| `date_of_birth`      | VARCHAR           | nullable               | String, not DATE type        |
| `profile_pic_url`    | VARCHAR           | nullable               |                              |
| `role`               | VARCHAR           | default 'USER'         | `@Enumerated(EnumType.STRING)` — stored as text |

> **Column name mapping**: Hibernate's default `SpringPhysicalNamingStrategy` converts camelCase Java fields to snake_case column names.

## MongoDB — ActivityService

### Connection

```yaml
uri: "mongodb://localhost:27017/WefitActivitydb"
database: "WefitActivitydb"
```

### Collection: `Activities`

**Entity**: [Activity.java](file:///c:/Wefit/activityService/src/main/java/com/wefit/activityService/entities/Activity.java)  
**Repository**: [ActivityRepository.java](file:///c:/Wefit/activityService/src/main/java/com/wefit/activityService/repositories/ActivityRepository.java)

```json
{
  "_id": ObjectId("..."),             // Auto-generated by MongoDB
  "activityType": "RUNNING",          // String (enum name)
  "durationInMinutes": 45,            // Integer
  "userId": 1,                        // Long (FK to PostgreSQL users.id)
  "caloriesBurned": 350,              // int
  "startTime": ISODate("..."),        // LocalDateTime
  "metrics": {                        // @Field("metrics") — renamed from additionalMetrics
    "distance_km": 5.2,
    "avg_heart_rate": 145
  },
  "createdAt": ISODate("..."),        // @CreatedDate (via @EnableMongoAuditing)
  "updatedAt": ISODate("...")         // @LastModifiedDate
}
```

**Auditing**: Enabled via [MongoConfigurations.java](file:///c:/Wefit/activityService/src/main/java/com/wefit/activityService/config/MongoConfigurations.java) with `@EnableMongoAuditing`.

**Repository issue**: `ActivityRepository extends MongoRepository<Activity, Long>` but `Activity.id` is `String`. The ID type parameter should be `String`.

### Indexes
- `_id`: Default MongoDB index (auto)
- No custom indexes defined

## MongoDB — AiService

### Connection

```yaml
uri: "mongodb://localhost:27017/AiRecommendationsdb"
database: "AiRecommendationsdb"
```

### Collection: `ai_recommendations`

**Entity**: [Recommendation.java](file:///c:/Wefit/aiService/src/main/java/com/wefit/aiService/entities/Recommendation.java)  
**Repository**: [RecommendationRepository.java](file:///c:/Wefit/aiService/src/main/java/com/wefit/aiService/repositories/RecommendationRepository.java)

```json
{
  "_id": ObjectId("..."),                        // Auto-generated
  "userId": 1,                                   // Long
  "activityId": "665f...",                       // String (Activity._id from WefitActivitydb)
  "recommendation": "Great job on your ...",     // String
  "improvements": ["Try to maintain ..."],       // List<String>
  "suggestions": ["Increase duration ..."],      // List<String>
  "safetyPrecautions": ["Stretch before ..."],   // List<String>
  "createdAt": ISODate("...")                    // @CreatedDate
}
```

### Repository Query Methods

```java
List<Recommendation> findTop5ByUserIdOrderByCreatedAtDesc(Long userId);
Recommendation findByActivityId(String activityId);
```

- `findTop5ByUserIdOrderByCreatedAtDesc` — Returns the 5 most recent recommendations for a user
- `findByActivityId` — Returns the recommendation generated for a specific activity

### Indexes
- `_id`: Default MongoDB index (auto)
- Consider adding indexes on: `userId`, `activityId`, `createdAt`

## Cross-Database References

Activities and recommendations reference users by `userId (Long)`, but there is **no referential integrity** across the PostgreSQL/MongoDB boundary. The only validation is the runtime REST call from ActivityService → UserService.

```
PostgreSQL.users.id  ←──(validated via REST)──  MongoDB.Activities.userId
PostgreSQL.users.id  ←──(no validation)──────  MongoDB.ai_recommendations.userId
MongoDB.Activities._id  ←──(logical FK)──────  MongoDB.ai_recommendations.activityId
```
